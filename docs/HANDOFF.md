# Handoff: родительский контроль для Windows

Обновлено: 2026-11-26

## Цель

Сделать программу для Windows, которая следит за игровым временем ребёнка и ограничивает его. Нужна альтернатива Time Boss: тот **закрывает все программы на время паузы**, а здесь **программы закрываться не должны** (только блокироваться или замораживаться).

## Требования пользователя

- **Ребёнок:** 10 лет, своя учётная запись Windows **без прав администратора**.
- **Лимиты:** дневной лимит в часах. Лимит **по типам программ** (категориям) — например «Игры», «Учёба», «Видео», «Неизвестное». Отдельный лимит только на игры пока не нужен, но категории должны это позволять.
- **Паузы:** правило вида «N минут → перерыв M минут». Во время перерыва программы **не закрываются**.
- **Расписание:** разрешённые часы работы по дням недели.
- **Программы:** разрешённые и запрещённые.
- **Интернет:** браузеры **пока полностью запретить**. Сам интернет нужен играм и Steam, поэтому весь интернет не закрывать.
- **ИИ:** определять категорию новых программ через ИИ. У пользователя есть **сервер в локальной сети** (Proxmox): на нём можно поднять ИИ-прокси, хранить статистику и управлять системой.

## Принятое решение

Доработать форк **DarkTama/WindowsParentalControl** (MIT, C#/.NET 8, около 12 тыс. строк, последний коммит upstream `50fad83` от 2026-10-07).

Отвергнуты:
- **ziur-vela/parental-opcontrol** — лицензия PolyForm Noncommercial; при исчерпании лимита убивает процесс (`process.Kill(entireProcessTree: true)`).
- **Pensarei/MonitorAndControl** — закрывает игры.
- **vasyaod/parental-control** — только общий лимит на пользователя.
- **Microsoft Family Safety** — закрытый код, облако, нет перерывов.

## Найденные проблемы

1. **Лимит только на весь сеанс — решено на этапе 1** (PR #3): категории, App Rules, App Limit, приостановка процессов.
2. **Подделываемые данные о программах.** Агент шлёт POST на `http://127.0.0.1:5050/api/agent/activity` без аутентификации (`Agent/ActivityTracker.cs:85`, `Service/Web/WebServerHost.cs:654`). Сейчас это только статистика. Когда от этих данных начнут зависеть лимиты, это станет дырой.
3. **Веб-панель открыта всем.** `ListenAnyIP(5050)` по HTTP (`WebServerHost.cs:41`).
4. **Повторный вход после блокировки — скорее всего уже решено.** `ParentalControlServiceLifetime.OnSessionChange` ловит `SessionUnlock`/`ConsoleConnect`, а `SessionTracker.cs:280–337` сразу блокирует снова. Старый handoff говорил «до 60 с». Проверить на VM 102.
5. **Расхождение в документах.** README говорит «forced logoff» и «lock»; `CONTEXT.md` описывает `LockWorkStation`, а код вызывает `WTSDisconnectSession`.
6. **Обновления шли из upstream — исправлено частично.** На этапе 0 `AppVersion.GitHubRepo` = форк: кнопка обновления больше не предлагает сборку upstream. У форка пока нет релизов, проверка отвечает «нет обновлений». Первый релиз форка — версия выше 1.5.0.
   Осталась дыра: `POST /api/admin/update/apply` (`WebServerHost.cs:1526-1539`) берёт `downloadUrl` из тела запроса и запускает этот exe с `/VERYSILENT` от имени администратора. URL не проверяется. Вместе с проблемой 3 (панель по HTTP на всех IP) это значит: кто прошёл вход в панель, может поставить любой exe. Закрыть на этапе 3: служба сама берёт URL из релиза форка, а не из запроса.
7. **`.claude/settings.local.json` в git** — мусор автора upstream (пути `C:/Users/Robert/...`).
8. **Хранимый XSS в веб-панели (upstream).** Таблица Grace Request вставляет `reason` ребёнка в `innerHTML` без экранирования. Скрипт ребёнка выполнится в сеансе родителя и может вызвать `/api/admin/grant`. Отдельный PR-исправление.
9. **Приостановленная программа блокирует выход и выключение.** Она не отвечает на запрос Windows о завершении сеанса: Windows показывает «Это приложение мешает выходу». Без нажатия Windows отменяет выход и выключение; «Всё равно выйти» закрывает игру. Окно приостановленной программы не сворачивается. Исправление — отдельное изменение: агент перед завершением сеанса просит службу возобновить программы, а перед приостановкой сворачивает окно.
10. **Состояние блокировки сеанса (upstream).** `SessionTracker.SynchronizeSessions` каждую минуту берёт `IsLocked` из `GetLoggedOnSessions`, а тот считает сеанс после Win+L разблокированным. После перезапуска службы заблокированный сеанс тоже считается разблокированным.
11. **Агент запускается заново каждую минуту (upstream).** `EnsureAgentRunning` не видит работающий агент и запускает второй, тот сразу выходит. В журнале строка «Successfully launched Agent» каждую минуту.
12. **Тексты по умолчанию на индонезийском.** Пользователь хочет немецкий по умолчанию: пресет `de` для всех сообщений — отдельное изменение.
13. **Предупреждение App Limit без учёта программы.** Служба предупреждает о каждом лимите, где осталось 1–5 минут, даже если ребёнок эту программу сейчас не использует.
14. **Telegram-оповещение о сбое приостановки не проверено:** на VM нет бота и чата.

## План работ

Каждый этап — одно или несколько изменений OpenSpec (`/opsx:propose` → одобрение → `/opsx:apply` → проверка на VM → `/opsx:archive`).

### Этап 0. Подготовка (сделано, кроме последнего пункта)
- `AppVersion.GitHubRepo` → форк (проблема 6). Готово, но см. остаток проблемы 6.
- `ci.yml`: сборка + тесты на `windows-latest`. Живой запрос к GitHub API в тестах пропускается на Actions (лимит запросов на общих IP). Готово.
- Вынести чистую логику из тестов, чтобы её можно было запускать на Mac. Сделать вместе с этапом 1: новая логика категорий сразу без WinAPI.

### Этап 1. Категории (сделано, PR #3)

Сделано так (подробно — `openspec/changes/add-app-categories/`, после архивации — `openspec/specs/app-categories`, `category-limits`):
- 7 категорий: Games, Video, Social, Study, Creative, System, Unknown. Лимиты по умолчанию 120/180 мин для Games, Video, Social, Unknown. Правила по имени exe и по папке; App Limit на правиле, время общее с категорией. Бонус добавляется к каждому лимиту.
- Лимит исчерпан → `NtSuspendProcess` только для программ, которые были на переднем плане сегодня. Никогда: System, папка Windows, агент, `msedgewebview2.exe`. Возобновление: новый день, бонус, смена лимита или правила, остановка службы. Не удалось приостановить → блокировка сеанса и одно Telegram-оповещение.
- Предупреждения за 5 и за 1 минуту, одно сообщение о паузе, звук выключает агент. Приостановленная программа на переднем плане время не тратит. Store-приложения агент сообщает по exe приложения, а не `ApplicationFrameHost.exe`.
- Логика без WinAPI — `src/ParentalControl.Domain`, тесты xUnit на Mac.

Исходный план:
- Таблицы `categories (id, name, daily_minutes, ...)` и `app_rules (match по пути / имени / издателю из подписи / SHA256 → category_id, blocked)`.
- Учёт минут по категориям в `UsageMonitorWorker`. Общий лимит остаётся.
- Лимит категории исчерпан → не блокировать сеанс, а:
  - замораживать процессы категории (`NtSuspendProcess`);
  - выключать им звук;
  - показывать сообщение через агента.
- Утром или после бонусного времени — `NtResumeProcess`.
- Неизвестные программы → категория «Неизвестное» со строгим лимитом.
- Настройка в Admin и в веб-панели.

### Этап 2. Перерывы и запреты
- Перерывы «N минут → M минут», глобально или для категории. На перерыв — `LockSession`.
- Предупреждения за 5 и за 1 минуту (`NotificationManager.SendWarning`).
- Запрещённые программы закрывать при запуске (WMI `Win32_ProcessStartTrace` или опрос).
- Браузеры: chrome, firefox, msedge, opera, yandex (browser.exe) и другие. **Не трогать `msedgewebview2.exe`.**

### Этап 3. Надёжность
- `/api/admin/update/apply`: не брать URL из запроса (остаток проблемы 6).
- Служба сама перечисляет процессы в сеансе ребёнка (`Process.SessionId`). Данные агента — только подсказка.
- Защищённый канал агент → служба: named pipe с проверкой SID и пути к exe, или токен.
- Веб-панель: только локальная сеть или вынести на сервер, HTTPS.

### Этап 4. Сервер и ИИ
- Новая программа → сервер в локальной сети. Метаданные: путь, имя, ProductName/CompanyName/FileDescription, издатель подписи, папка (`steamapps\common`, `Epic Games`), заголовок окна, командная строка, SHA256.
- На сервере: кэш → жёсткие правила → LLM (OpenAI-совместимый endpoint). Ответ — строгий JSON: категория из списка + уверенность.
- Низкая уверенность → запрос родителю в Telegram. Решение родителя важнее ИИ и становится правилом.
- Пока программа не опознана, она считается «Неизвестным», время идёт.
- Данные из exe — недоверенные (prompt injection).
- Клиент хранит правила у себя и работает без сервера, статистику досылает.

## Решения пользователя (2026-11-25)

- Правило «chore идёт в PR без OpenSpec» остаётся.
- Категории придумать самим. Общее правило: 2 ч в будний день, 3 ч в выходной.
