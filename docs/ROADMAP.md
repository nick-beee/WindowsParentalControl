## Цель

Программа для Windows, которая ограничивает игровое время ребёнка. Альтернатива Time Boss: тот **закрывает все программы на время паузы**, а здесь программы **не закрываются** — только блокируется сеанс или замораживаются процессы.

## Требования пользователя

- **Ребёнок:** 10 лет, своя учётная запись Windows **без прав администратора**.
- **Лимиты:** дневной лимит по категориям программ («Игры», «Учёба», «Видео», «Неизвестное»), у отдельных игр — свой лимит.
- **Перерывы:** правило «N минут → перерыв M минут». Во время перерыва программы не закрываются.
- **Расписание:** разрешённые часы по дням недели.
- **Программы:** разрешённые и запрещённые.
- **Интернет:** браузеры пока полностью запретить. Сам интернет нужен играм и Steam.
- **ИИ:** определять категорию новой программы через ИИ на сервере в локальной сети (Proxmox).

### Этап 2. Перерывы и запреты

- Перерывы «N минут → M минут» для всего сеанса — сделано (change `add-usage-breaks`, PR #31, спека `openspec/specs/usage-breaks`). На перерыв — `LockSession`, программы остаются открытыми. Предупреждения за 5 и за 1 минуту. Карточка «Pausen» в веб-панели, `/break` в Telegram.
- **После обновления перерывы включены** (45/10, решение D2). Это должно быть в release notes версии.
- Следующее изменение: перерывы для категории (приостановить программы одной категории).
- Запрещённые программы — сделано (change `add-blocked-programs`, PR #33, спека `openspec/specs/blocked-programs`): блок на App Rule, закрытие только **при запуске** (WMI `Win32_ProcessStartTrace` + тик 60 с), уже запущенная программа приостанавливается. 15 браузеров заблокированы по умолчанию, `msedgewebview2.exe` не трогается. Проверено на VM 102 (2026-11-26). Открыто: уведомление в Telegram (#13) и проверка на ПК ребёнка. Решения: `openspec/changes/archive/2026-11-26-add-blocked-programs/design.md`.
- #52 — кнопка «Mehr Zeit wünschen» открывала браузер, а браузеры заблокированы. В работе: change `show-request-page-in-agent-window`, PR #54, ADR 0014. Агент показывает страницу запроса в своём окне (Request Window, WebView2), установщик ставит WebView2 Runtime, если его нет. Код готов, осталась проверка на VM 102 (группа 7 в `tasks.md`). Связь с #43: Agent Window Budget (задача 6.1). **В release notes:** кнопка запроса открывает окно Parental Control, а не браузер; установщик может установить WebView2 Runtime.
- Потом: режим «только разрешённые программы» (allow-list) и распознавание переименованного или портативного браузера (ресурс версии или подпись).
- Связанное: #11 (немецкий по умолчанию), #12 (предупреждения App Limit).

### Этап 3. Надёжность

- #6 и #32 — канал агент → служба без аутентификации; процесс ребёнка блокирует агента через его мьютекс. Сделано: change `session-probe-and-agent-channel`, PR #43, ADR 0011, архив `openspec/changes/archive/2026-11-28-session-probe-and-agent-channel`. Проверено на VM 102 (2026-11-28), включая обновление с 1.5.0. Окно переднего плана определяет служба сама через Session Probe (процесс SYSTEM в сеансе ребёнка); Category Usage — только по его выборкам, данные агента ни один лимит не читает. Агент говорит со службой только через Agent Channel (именованный канал только для SYSTEM, клиентский конец служба передаёт агенту при запуске); старые HTTP-маршруты агента удалены (404). Агента запускает только служба: мьютекса больше нет, установщик удаляет значение `ParentalControlAgent` из `Run`. Блокировки пробы (Probe Lock) сначала в Shadow Mode: `probe_locks_enforced` выключен, служба только пишет `PROBE_WOULD_LOCK` и оповещает родителя. Перед релизным тегом: #63 — #48 (задача 7.4), задача 9.1 на ПК ребёнка и задача 9.2 (Window hook на VM). **В release notes:** блокировки пробы выключены, родитель включает их в веб-панели после 7 дней без ложных «would lock».
- #53 — страница запроса ребёнка (`/request`, `/api/request`) верила имени пользователя из запроса и показывала список всех Restricted Users. В работе: change `request-identity-from-launch` (draft PR). Окно запроса получает Request Token от службы через Agent Channel (cookie HttpOnly); служба берёт пользователя и сеанс только из launch record токена, без токена — 401. Код готов, осталась проверка на VM 102 (группа 7 в `tasks.md`).
- #7 — веб-панель на всех IP по HTTP.
- #8 — `update/apply` запускает exe по URL из запроса.
- #9, #10, #14 — ошибки `SessionTracker` (состояние блокировки, перезапуск агента, повторная блокировка).
- #13 — проверить Telegram-оповещение о сбое приостановки.
- #36, #37 — часовой пояс и полный диск — сделано (change `harden-clock-and-disk`, PR #40, спеки `openspec/specs/control-clock` и `openspec/specs/storage-failure`). Лимиты считают день по Control Time Zone, а не по поясу Windows. При полном диске служба блокирует сеанс (Storage Lockdown). Проверено на VM 102 (2026-11-27), часть — только с тестовым переключателем (см. «Итоговая проверка на ПК ребёнка»).

### Этап 4. Сервер и ИИ

- Новая программа → сервер в локальной сети. Метаданные: путь, имя, ProductName/CompanyName/FileDescription, издатель подписи, папка (`steamapps\common`, `Epic Games`), заголовок окна, командная строка, SHA256.
- На сервере: кэш → жёсткие правила → LLM (OpenAI-совместимый endpoint). Ответ — строгий JSON: категория из списка + уверенность.
- Низкая уверенность → запрос родителю в Telegram. Решение родителя важнее ИИ и становится правилом.
- Пока программа не опознана, она в Unknown, время идёт.
- Данные из exe — недоверенные (prompt injection).
- Клиент хранит правила у себя и работает без сервера, статистику досылает.
- Сервер — отдельный LXC на pve2, приложение в `ansible-proxmox`.

## Итоговая проверка на ПК ребёнка

- Session Probe (#63, задача 9.1 архивированного `session-probe-and-agent-channel`): сборка только с журналом; обычные программы и час обычной работы, нагрузка CPU, быстрая смена пользователя, Windows Terminal, сон и пробуждение; версия, редакция Windows и Modern Standby ПК ребёнка. Блокировки пробы остаются выключенными, пока эта проверка не пройдёт.

VM — не ПК ребёнка. На ПК ребёнка проверить:

- Запрещённые программы (`add-blocked-programs`).
- Предупреждение о часовом поясе в Parental Control Admin (`harden-clock-and-disk`, задачи 6.3 и 6.5): после `tzutil /s` под ребёнком администратор видит в Admin оба пояса, тот же день и предупреждение. На VM не проверено: Admin нужна консоль администратора, а консоль занята `Kid`.
- Storage Lockdown на реально полном диске (`harden-clock-and-disk`, задачи 6.8 и 6.9): ребёнок заполняет диск — в пределах 3 тиков сеанс блокируется, событие 1015, одно оповещение; после освобождения — событие 1016, минуты не теряются. На VM 102 Reserved Storage не даёт записи упасть; проверено только тестовым переключателем `PARENTAL_CONTROL_TEST_WRITE_FAIL`. Если и на ПК ребёнка есть Reserved Storage (`fsutil storagereserve query C:`), запись тоже не упадёт; тогда проверить, что лимиты и счёт времени продолжают работать на полном диске.
- Lock Deferral при выходе (`defer-lock-during-session-end`, задача 4.8): несохранённый текст в Блокноте переживает блокировку по лимиту, по расписанию, на перерыв и запасную блокировку в начале выхода; Windows ждёт меньше 75 с (на VM 102 — 65 с); «Bonus Minutes во время отсрочки» — после отсрочки действует новый остаток.
- Окно запроса в агенте (`show-request-page-in-agent-window`, задачи 7.3 и 7.9): запрос из окна приходит родителю в Telegram; у администратора в консоли нет виджета и пункта «Mehr Bildschirmzeit wünschen…» в трее.
- Session Probe (`session-probe-and-agent-channel`, задача 9.1, design D15) — до релизного тега, сборкой спайка, которая только пишет лог (не блокирует, не замораживает, не закрывает), считает кодом `ParentalControl.Domain` (после задач 2.1–2.3) и ставится на ПК ребёнка одна: только `ProbeSpike` без тестовых ключей (без `-p:VmTest=true`), без `SpikeKid`, `TestGame` и других инструментов атаки; после проверки службу и все файлы спайка удалить и записать это: версия и редакция Windows и Modern Standby (`powercfg /a`); обычные программы (Word, Edge, Chrome, Store-приложение, лаунчер игр, экранная клавиатура, уведомление, «Новости и интересы», виджет и меню агента в трее) и час обычной работы — нет чужой категории, нет blind sample, не больше 2 budget items за 10 минут; нагрузка CPU 10 минут программами самого ребёнка (игра и вторая программа с приоритетом High) с игрой — время Games не меньше реального минус 1 минута, нет разрыва длиннее 60 с и нет gap item (на VM 102 разрывы до 34 с, причина не подтверждена); сон три раза за 10 минут — нет `PROBE_RESTART`, `PROBE_OUTAGE` и budget item; переключение между игрой и Study-программой под нагрузкой с движением мыши — нет ложного полного счёта и ложных gap items; выход и выключение, а также выход с несохранённым текстом в Блокноте (Cancel, затем «Всё равно выйти») — нет `PROBE_RESTART` и budget item. Если Windows 11 — проверки обычных программ и нагрузки CPU и там. Пока задача 9.1 не пройдена, `probe_locks_enforced` выключен.
