# 11. A SYSTEM Session Probe Gives the Facts, and a Private Channel Connects the Session Agent

## Status
Proposed (change `session-probe-and-agent-channel`). Replaces point 1 of [ADR 0002](0002-session-agent-for-app-tracking-and-tray.md).

## Context
ADR 0002 made the Session Agent the source of the Foreground Window, because a service in session 0 cannot read the windows of another session. Since `add-app-categories`, two limits depend on the agent samples: Category Usage and the set of exes that the service may suspend. The agent sends them over HTTP to `127.0.0.1:5050` without authentication, so any process of the child can send false samples (issue #6). Any process of the child can also stop the agent with its named mutex (issue #32).

The agent runs as the child. The child can kill it, read its memory, inject code into it (`SetWindowsHookEx`, `CreateRemoteThread`, a debugger, `DOTNET_STARTUP_HOOKS` in its own environment), and copy its handles with `DuplicateHandle`. So no secret and no check of the agent process can make agent data trustworthy. The rule of `CLAUDE.md` says that a limit must never depend on such data.

## Decision
1. **A Session Probe gives the facts.** The service starts `ParentalControl.Probe.exe` in each session of a Restricted User with a SYSTEM token that it moves to that session (`SetTokenInformation(TokenSessionId)`), without privileges, with the environment of SYSTEM minus the .NET runtime variables, with a SYSTEM-only DACL on its process and thread, at High priority with a time-critical sampler thread, and with `DETACHED_PROCESS`, so that no console host starts. The probe is a self-contained .NET 10 console program with no window and no reference to the other projects. At random times, at least 0.2 and about 5 seconds apart, it reads the Foreground Window, the focus window, the visible child windows of other processes in the Foreground Window, and the window under the cursor with its parent windows, and sends their window handles, thread IDs and process IDs with its own sample time through an anonymous pipe that only the service and the probe hold. The probe opens no process of the child.
2. **The service reads the process.** The service enables `SeDebugPrivilege` and reads the exe path, the session and the start time of each sampled process itself, so that a DACL of the child on its game does not hide the game. Category Usage, the Foreground Window history and App Usage take only these reads. The time counts for each non-System process among the Foreground Window, the focus, and the foreign child windows, and for each process under the cursor if the top-level window there has `WS_EX_NOACTIVATE`; each sampled exe becomes a suspend candidate. A process of the WebView2 Runtime in Program Files counts as the program that started it (its parent chain); if that program ended or the chain fails a check, it counts nothing and never feeds the budget, because WebView2 apps can share one browser process. Another `msedgewebview2.exe` counts as itself. The window of the Session Agent counts in Unknown, also as a child window, except during an active prompt of the parent. The service decides whether a sampled entry ended by its thread, not by the wall clock. A program that is never suspended locks the session after 60 seconds in an exhausted category. The widget of the agent does not take the activation (`WS_EX_NOACTIVATE`), so a click on it does not make the agent count. The service measures the time with the sample time of the probe.
3. **No samples, no category time; blind samples lock the session.** If the probe gives no samples (a fault), no category time counts, the service starts a new probe, and the parent gets an alert after 5 minutes. A watchdog ends a silent probe after 30 seconds. After an end, the service starts a new probe within 10 seconds, and it classifies the end 90 seconds later: an end that the sign-out, the end of the session or a service stop follows in that time is a session-end end and counts for nothing. Frequent unexpected ends count toward the budget below. A gap between two samples with the same programs (the same exes and categories) counts in full, at most 60 seconds; a long gap with other programs, or a sample that took more than 12 seconds, is a budget item, and the parent gets one alert per day about long gaps. A resume from sleep is handled like an unlock: the watchdog and the outage timer use the unbiased interrupt time, and the first sample after a resume adds no time. A blind sample is one that the service cannot attribute to an exe: the child can create a desktop that denies SYSTEM, only a child action or a bug makes a sampled process unreadable, and more than 8 foreign processes in the Foreground Window can hide a game. A counted process that ended before the read only counts toward the budget. At the 6th item within 10 minutes of unlocked time, and after that lock at each blind sample of that day, the service applies the Enforced Workstation Lock and alerts the parent. The random sample times keep the child from timing a switch between two samples. The service never uses agent data instead. Content of a sample (a title, a desktop name) never ends the probe.
4. **A private Agent Channel.** For each agent start, the service creates a named pipe that only SYSTEM can open, opens the client end itself, and gives that handle to the agent by inheritance (`PROC_THREAD_ATTRIBUTE_HANDLE_LIST`). The agent checks that the server runs in session 0. The service takes the user and the session of each message from the launch, never from the message. It treats the channel as hostile input: a length check before each read, asynchronous I/O with timeouts, and a rate limit.
5. **The agent gets no trust.** The channel proves the session and the user, not that the agent code sent the data. The agent only shows texts, mutes and minimizes windows, answers prompts, uploads captures, and asks for a Session End Hold under its rate limit.
6. **The service owns the single instance.** It starts one agent per session and keeps its process handle. The agent has no mutex, and an agent without a channel exits. The installer removes the `Run` key of the agent.
7. **The HTTP agent routes go at once.** `/api/agent/*` answers 404 in the same release. The child request page and the web admin stay on HTTP.
8. **The probe locks start in a shadow mode.** The locks that this change adds (after blind samples, for a program that is never suspended, for a full set of exes) apply only after the parent switches them on in the web admin. Until then the service logs and reports each one as "would lock", with one alert per day for each reason and for each exe that is never suspended, and it still counts and suspends from the probe. The first release runs so on the child's PC for some days.
9. **The design stops the chase of script bypasses.** Three review rounds each found a new window trick with a script. After the third, each remaining class that needs a script or code is accepted and listed without a bound in the design, with the mitigation of the parent. A later finding goes into that list unless its fix is cheap and adds no false-lock risk.

### Rejected alternatives
- **A helper that runs as the child**: the same weak point as the agent.
- **Agent samples checked against the process list**: the child reports a Study exe that runs in the background while a game is in front.
- **Count from the process list only**: launchers and tray helpers count all day (`add-app-categories` D1).
- **A named pipe with an ACE for the child and a check of the client process** (`GetNamedPipeClientProcessId`, image path, session, pid and start time): it proves no more than the inherited handle, and it needs a correct ACE without `FILE_CREATE_PIPE_INSTANCE`, a pid check with a race, and a reconnect logic. It stays the fallback if the VM shows that the inheritance across sessions fails.
- **A secret token for the agent**: the child reads the memory and the command line of its own agent.
- **The agent at High integrity level**: its child programs inherit the level, and the side effects on the shell, the tray and the audio APIs are not known. The probe makes this protection unnecessary.
- **A mutex that only SYSTEM can create**: the child can create the name first while the service is not running. The channel already gives one agent per session.
- **Keep the HTTP routes for one version**: this keeps #6 open for that version, and the installer ships the agent and the service together.
- **A probe that opens the window process itself**: the child can remove SYSTEM from the DACL of its game, and a probe without privileges then sees nothing.
- **A lock after 30 seconds of only unreadable samples**: a short return to the default desktop resets the timer, so the child alternates and is never locked.
- **Count only the Foreground Window and the focus**: a script can put an unchanged game into a System window, and the focus stays on the host, or it can set `WS_EX_NOACTIVATE` on a game.
- **Count each window under the cursor**: the cursor often rests on a window that the child does not use, so this would charge the wrong category often.
- **Trust `msedgewebview2.exe` by its file name**: the child can copy a game with that name.
- **A Job Object for the probe**: a job in session 0 cannot hold a process of another session.
- **`CREATE_NO_WINDOW`**: it still starts a hidden console host for the probe.
- **A start-time test for each sampled entry**: the wall clock can step, so an honest entry looks reused and feeds the lock; the thread test already excludes a reuse.
- **A trusted WebView2 counted with the Foreground Window**: a script moves the control into Notepad, and a WebView2 popup of a Study app counts as Unknown.
- **The probe locks on from the first release**: the VM cannot show that false blind samples are absent on the child's PC, and the strike makes each one a lock.
- **Shadow counting with the agent samples as the source**: it opens issue #6 again.

## Consequences
- No limit reads data of a process that the child controls. The child can still fake its own screen captures, answer its own prompts, get about 80 seconds of play per 15 minutes with a false session-end request, and stop its own widget.
- Each bypass that needs a script or code of the child (injected code in a System program, a Windows script host that shows a game, a window trick that keeps a game out of each sampled role, a WebView2 with a false parent) counts no time and is never suspended. These residual risks have no bound; the design lists each class. A parent can move script hosts such as `powershell.exe` and `mshta.exe` out of System with an App Rule, and block third-party script tools.
- Until the parent switches the probe locks on, a hidden desktop or a program that is never suspended gives free time with a daily alert. A game copied as `msedgewebview2.exe` needs no script for this, so GitHub issue #48 (suspend such a copy by its path) is a prerequisite of the release.
- The full-screen settings dialog and the tray menu of the agent still take the activation. A child who leaves the dialog in front for more than 60 seconds while Unknown is exhausted is locked.
- A WebView2 popup of the second instance of an app whose first instance ended counts nothing.
- The children and the `WS_EX_NOACTIVATE` cursor rule can charge a second category in a case that the VM spike did not log. The spike gates this.
- A SYSTEM process runs in the session of the child. A bug in it is a way to SYSTEM, so the probe has no window, no privileges, no environment of the child, and files that only administrators can change. Native AOT is a later option.
- A probe fault stops the category counting until the probe runs again. The parent gets an alert. The session Allowance Time is not affected.
- A child that hides on a desktop that denies SYSTEM, or behind a DACL that the service cannot pass, gets the Enforced Workstation Lock, not free time. A false blind sample from Windows would lock the child, so the VM spike must show none for UAC, Ctrl+Alt+Del, the secure screen saver and a fast user switch.
- All projects move from .NET 8, which is out of support, to .NET 10 before this change.
- The probe has no Job Object. The pipe ends the probe with the service, and the service ends leftover probes at its start.
- The installer must ship and stop the probe. An old agent that survives an update gets 404 and shows a stale widget until the next sign-in.
- A later change can move the screen capture into the probe, so that the child cannot fake it.
