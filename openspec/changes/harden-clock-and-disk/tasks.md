## 6. Integration checks on the VM

- [ ] 6.1 Time zone and reboot: as `Kid`, use all Allowance Time (a limit of 2 minutes), run `tzutil /s "Tokyo Standard Time"`, and restart the VM; expected: after the sign-in of `Kid` the session locks at once, the Admin app shows the same day and the warning, and the event of the change is in the events table.
- [ ] 6.2 Schedule Window: set the Schedule Window to end 5 minutes from now in the Control Time Zone, then as `Kid` set a zone 3 hours behind and restart; expected: the session locks at the end of the window in the Control Time Zone.
- [ ] 6.3 Daylight saving: while `Kid` is signed out, set the VM clock as an administrator to 02:50 local time on 2026-10-25 (the end of daylight saving time in "W. Europe Standard Time"), and turn off the automatic time sync. Wait two ticks, so that the clock watchdog event of the set itself is over. Then sign in as `Kid` with a large limit; expected: after 03:00 goes back to 02:00, no new `CLOCK_TAMPER` event, no lock, and the Allowance Time grows by the real minutes only. Set the clock back to the real time as an administrator after the check.
- [ ] 6.4 Full disk: as `Kid`, fill the system disk with `fsutil file createnew %USERPROFILE%\fill.bin <free bytes>` while a test game runs; expected: the service locks the `Kid` session within 3 ticks, event 1015 is in the event log, one Telegram alert line is in the service log, the test game is still open after the next sign-in, and the session locks again within 2 seconds.
- [ ] 6.5 Free the disk: as `nick`, delete `C:\Users\Kid\fill.bin`; expected: within 60 seconds event 1016, the stored Allowance Time includes the minutes of the failed ticks, and `Kid` can sign in and play as normal. Then fill and free the disk a second time on the same day; expected: event 1015 again and no second alert line.
- [ ] 6.6 Roll back VM 102 to `test-base`; verify `ssh winvm` works and Parental Control is not installed.
