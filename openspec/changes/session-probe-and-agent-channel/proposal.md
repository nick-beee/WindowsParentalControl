# Proposal

## Why

Two limits depend on data that any process of the child can send to `127.0.0.1:5050` without authentication (GitHub issue #6). Category Usage counts the Foreground Window samples of `POST /api/agent/activity`, and only an exe from these samples can become a Suspended App (`ForegroundHistory`). A script that sends a Study exe every 20 seconds keeps the Games time at zero, and a game that never shows in a sample is never suspended. This breaks the rule in `CLAUDE.md`: a limit must never depend on data that the Session Agent sends without authentication.

Also, any process of the child can stop the Session Agent: it creates the named mutex `Global\ParentalControlAgent_{UserName}` first, and the real agent exits at its start (GitHub issue #32).

The child runs the Session Agent under its own account. So the child can read the memory of the agent, inject code into it, and kill it. A secret or a check of the agent process cannot make agent data trustworthy. The service must get the facts for a limit from a source that the child cannot change.

## What Changes

- **Session Probe** (new): the service starts a small helper process in each session of a Restricted User. The helper runs as SYSTEM, has no window, and the child cannot stop, read or change it. At random times, about every 5 seconds, it reads the windows of the input desktop that the child can use: the Foreground Window, the focus window, the visible child windows of other processes in the Foreground Window, and the window under the cursor with its parent windows. It sends their window handles, thread IDs and process IDs, with its own time of the sample, to the service through a pipe that only the service and the helper hold. The helper opens no process of the child.
- The service reads the exe path and the start time of each sampled process itself, with `SeDebugPrivilege`, so a DACL that the child puts on its game does not hide the game. Category Usage, the set of exes that were a Foreground Window today, App Usage and the live activity on the admin page come only from these reads. The service measures the time between samples with the time of the helper, so a CPU load of the child that delays the service does not shorten the count.
- The time counts for each process that is not System among the Foreground Window, the focus window, and the child windows of other processes (for example, a game that a script put into a Notepad window). It also counts for each process under the cursor if the top-level window there cannot be activated by a click (`WS_EX_NOACTIVATE`), so that a game with this style, or a game inside a System window with this style, still counts while the child plays it with the mouse. Each of these exes, and the exe of each other process under the cursor, becomes a suspend candidate.
- A process of the WebView2 Runtime in Program Files counts, in each role, as the program that started it (found through its parent processes), so a WebView2 popup of a Study app counts as Study and a WebView2 control that a script moved into Notepad counts as its app. If that program ended (WebView2 apps can share one browser process) or the chain cannot be checked, the WebView2 counts nothing and never locks. Any other file with the name `msedgewebview2.exe` counts like any other exe.
- The Session Agent window counts in Unknown, not in System, also as a child window of another program, except while the parent has an active prompt for the child. If the category of a program that the service never suspends (for example the agent) is exhausted and that program counts for more than 60 seconds in 10 minutes, the service applies the Enforced Workstation Lock.
- The widget of the Session Agent no longer takes the activation: a click or a drag on it leaves the program in front as the Foreground Window, so a widget click never makes the agent count. The full-screen settings dialog and the tray menu still take it while they are open.
- A gap between two samples counts in full, at most 60 seconds, if both samples show the same programs; a long gap with other programs counts 12 seconds and is a budget item (see below). The VM spike measured gaps of up to 34 seconds under a CPU load of the child. A hung program counts as itself, not as the ghost window of `dwm.exe` that Windows shows for it. The locked state comes from the lock notification of Windows, not from the windows of a sample.
- If the Session Probe of a session gives no sample (a fault), the service counts no category time for that session, starts the probe again, and alerts the parent after 5 minutes without samples (at most one alert per hour). The session Allowance Time still counts as before. The service ends a probe that sends nothing for 30 seconds. When a probe ends, the service waits 15 seconds: if the session signs out or the service stops in that time, the end is expected (Windows ends the probe at a sign-out before the service knows about it). Else the service starts a new probe within 25 seconds after the end. It counts these ends, alerts the parent at the 3rd in an hour, and from the 3rd in 10 minutes each end counts toward the budget below. Sleep and hibernation are no fault: the service handles a resume like an unlock, so a resume never ends the probe for silence, never alerts, and never charges the sleep time.
- A blind sample is a sample that the service cannot attribute to an exe: the input desktop is not readable (the child can create a desktop that denies SYSTEM), the Foreground Window gives no thread, the service is denied a sampled process, or more than 8 other processes have windows in the Foreground Window. A counted process that ended before the service read it, and the unexpected ends of the probe above, also count toward the budget, but they never lock at once after the first lock of the day. At the 6th item within 10 minutes of unlocked time, the service applies the Enforced Workstation Lock and alerts the parent. After that lock, each blind sample of the day locks again. It closes no program.
- **Release gates on the child's PC**: the checks of the VM spike that need the child's PC (common programs and one hour of normal use, the CPU load, sleep, the Windows version) run there with a log-only build before the release. The probe locks stay off until they pass.
- **Shadow mode** (new): the locks of this change (after blind samples, for a program that is never suspended, for a full set of exes) start off. While they are off, the service logs and reports each lock as "would lock" and still counts and suspends. It alerts the parent once per day for each reason, and once per day for each exe of a program that is never suspended, with its path. The parent switches them on in the web admin after some days on the child's PC without a false "would lock".
- **Agent Channel** (new): the service starts the Session Agent with one end of a pipe that the service created. No other process can open this pipe by name. The agent uses only this channel: the status poll, the prompt answer, the screen capture upload and the session-end request.
- The service treats the Agent Channel as hostile input: it checks the length of a frame before it reads it, uses asynchronous reads and writes with timeouts, and limits the messages per channel. It starts the agent without the variables `DOTNET_*`, `COMPlus_*`, `CORECLR_*` and `WEBVIEW2_*`.
- The service takes the user and the session of each agent message from the agent that it started, never from a field in the message. A prompt answer must name an active prompt of that user. A status poll shows only the prompts and the capture requests of that user.
- **BREAKING**: the routes `GET /api/agent/status`, `POST /api/agent/activity`, `POST /api/agent/prompt/respond`, `POST /api/agent/session-ending` and `POST /api/agent/capture` go away in the same release. The installer ships the agent and the service together. `/`, `/request`, `/api/request` and the web admin stay on HTTP.
- **Single instance** (#32): the agent no longer uses a named mutex. The service starts one agent per session and keeps its process handle. It starts a new agent only after that process ended. An agent that the service did not start has no channel and exits at once. The installer removes the `Run` key that starts the agent at sign-in.
- The Session Agent stops the Foreground Window sampling. It gets the pids to mute from the status poll.
- The rate limit of the Session End Hold stays. The child controls its own agent, so a session-end request through the channel is still a claim of the child. The request starts the Lock Deferral and the hold or the Session End Guard, as on main.
- **Agent Window Budget** (from #54): the agent windows, such as the Request Window, are exempt for at most 5 minutes in any 60 minutes of unlocked time, from probe facts only. The two budget requirements move from `request-window` into `category-limits`.
- The probe locks go through the Lock Deferral, never stop for a failed write, and take each day from the Control Time Zone (design D14).

## Out of scope

- A repeated resume of a Suspended App with a tool (GitHub issue #24). The child still owns its processes. A separate change handles it.
- Idle detection. A program in front counts also if the child does not use it, as today.
- A program whose window is not in a sample: not the Foreground Window, not the focus, not a child window of the Foreground Window, and not a `WS_EX_NOACTIVATE` window under the cursor. Examples: a video in a background window, or a `WS_EX_NOACTIVATE` game that the child plays with the keyboard or a gamepad while the cursor rests elsewhere.
- A copied or renamed exe that matches the App Rule of another category. Rules by hash or by signature are a part of stage 4.
- A game in a folder below `C:\Windows` that a standard user can write (GitHub issue #45).
- Each bypass that needs a script or code of the child, for example a game drawn in its own `notepad.exe`, a PowerShell web control, an HTA file in `mshta.exe`, a window trick that keeps a game out of each sampled role, or a WebView2 with a false parent. design.md (D13 and "Accepted script and code bypasses") lists each class as accepted and without a bound, with the mitigation of the parent: an App Rule that moves the Windows script hosts out of System, and a block of third-party script tools.
- A game copied as `msedgewebview2.exe`: with the probe locks on, this change locks the session when its category (Unknown without a rule) is exhausted. In shadow mode it would play without a limit, so GitHub issue #48, which suspends such a copy by its path, is a prerequisite of the release (tasks.md 7.4); its own change follows the archive of this change.
- Screen captures from the Session Probe. The agent still makes them, so the child can fake them (see design.md, residual risks).
- The web server on all addresses over HTTP (#7), and `update/apply` (#8).
- A change of how the Allowance Time, the Schedule Window or the Enforced Workstation Lock works.
- Window minimization and mute in the session of another user.

## Capabilities

### New Capabilities
- `session-probe`: the SYSTEM helper in each session of a Restricted User that reports the Foreground Window to the service, its start and restart, its protection against the child, the read of a sampled process by the service, blind samples and the lock after them, the shadow mode of the probe locks, and what the service does when it gives no samples.
- `session-agent-channel`: the private channel between the service and the Session Agent that the service started, the identity of each message, its limits against a flood, the agent environment, the single agent per session, and the end of the HTTP agent routes.

### Modified Capabilities
- `category-limits`: Category Usage and the suspend candidates come from Session Probe samples, not from agent samples; the counted processes of a sample; WebView2 counts with the program that started it; a limit for the Session Agent window and for each program that is never suspended; the set of Foreground Window exes fails closed; the reason of the rate limit of the Session End Hold changes.
- `app-categories`: the untrusted exe data comes from the Session Probe.
- `admin-access`: the capture quota applies to the Agent Channel; `/api/agent/*` is no longer a child-facing route.
- `child-messages`: the service sends the Language Preset in the status of the Agent Channel.
- `session-lock`: the limit of the Lock Deferral names the session-end request of the Agent Channel; the old route gives no deferral.
- `storage-failure`: the Pending Usage scenario uses a Session Probe sample.
- `request-window`: the two Agent Window Budget requirements move to `category-limits` (REMOVED here, ADDED there with the same text).

## Impact

- A chore before the implementation moves all projects from .NET 8 (out of support since 2026-11-10) to .NET 10, with CI and the VM snapshot.
- New project `src/ParentalControl.Probe` (`ParentalControl.Probe.exe`, `net10.0-windows`, a console program without a window, self-contained, no reference to another project). The installer puts it in `{app}\probe`.
- `src/ParentalControl.Core/Platform`: new code to start a process in a session with a SYSTEM token, without a console, and with one inherited handle; `SessionManager.LaunchProcessInSession` returns the process handle; the service enables `SeDebugPrivilege` and reads a sampled process itself. The Foreground Window code of the agent `ActivityTracker` moves into the probe project.
- `src/ParentalControl.Service`: new `SessionProbeHost` and `AgentChannelHost`; `SessionTracker.EnsureAgentRunning` tracks the agent that it started; `CategoryEnforcer` and the counting take probe samples; `WebServerHost` loses the five agent routes, and the status, prompt, capture and session-end logic moves behind the channel.
- `src/ParentalControl.Agent`: `Program.cs` (no mutex, channel handle from the command line), `AgentController.cs`, `SessionEndWatcher.cs` (channel instead of HTTP), `ActivityTracker.cs` (removed), `WidgetWindow` (non-activating, design D5).
- `src/ParentalControl.Service/ParentalControlServiceLifetime.cs`: the power events also reach `SessionProbeHost` (the watchdog and the outage timer at sleep and resume).
- `src/ParentalControl.Domain`: pure classes for the sample counting, the counted processes (with the trusted WebView2 path, its creator, and the prompt exemption of the agent), the blind-sample budget, the probe outage and restarts, the shadow mode gate, the channel messages and limits, and the agent launch record; the cap of `ForegroundHistory` rises to 60,000. New xUnit tests.
- `installer/ParentalControl.iss`: the probe files; the `Run` key goes; the uninstall stops the probe.
- `src/ParentalControl.Core/Data/SettingsRepository.cs`: the setting `probe_locks_enforced` (off by default). `web/admin`: a switch for it on the settings page, with German texts. New `EventType` values `PROBE_OUTAGE`, `PROBE_BLIND`, `PROBE_RESTART` and `PROBE_WOULD_LOCK`.
- `GLOSSARY.md`: new terms Session Probe, Agent Channel, Blind Sample, Budget Item, Counted Process, Probe Lock and Shadow Mode; Category Usage and Session End Hold change.
- `docs/adr/0011-session-probe-and-agent-channel.md`: replaces point 1 of ADR 0002.
- No new table and no new column.
- Release prerequisite: the change of GitHub issue #48 (tasks.md 7.4).
