All VM checks run on test VM 102 as `Kid` in the Proxmox console (noVNC or SPICE), not over RDP. Before you install the service, check that the snapshot `test-base` exists (`docs/vm.md`). Use a test exe in Games with a Games limit of 2 minutes, as in `add-app-categories` task 6.2. Record each VM result with date and times in this file and in the PR.

## 1. VM spike: Windows behaviour that the design assumes

Do this group before group 3. If a check fails, stop and run `/opsx:update` with the fallback that design.md names.

- [ ] 1.1 Build a test service and two test programs in `scripts/vm/` (outside the product). The service creates a SYSTEM-only named pipe with `FILE_FLAG_FIRST_PIPE_INSTANCE`, opens the client end itself, and starts one program with the token of `Kid` and one with a SYSTEM token moved to the session of `Kid` (design D2 and D7), each with `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` and the handle value on the command line. Verify on the VM: both programs read and write through the inherited handle, `GetNamedPipeServerSessionId` returns 0 in the program of `Kid`, and `Kid` cannot open the pipe by its name (`[System.IO.Pipes.NamedPipeClientStream]` in PowerShell gives "access denied").
- [ ] 1.2 In the SYSTEM test program, sample every 5 s as design D4 states and log each sample. Verify on the VM: a game window of `Kid` in front gives its exe path; the Windows Calculator gives `CalculatorApp.exe`; the lock screen gives the desktop `Winlogon` and no window; after `Kid` creates and switches to a second desktop with Sysinternals Desktops and starts the test game there, the samples name the test game; after `Kid` creates a desktop with `CreateDesktopW` and a security descriptor for `Kid` only and switches to it, `OpenInputDesktop` or `SetThreadDesktop` fails in the SYSTEM program (record which). Also log a window with a title of 10,000 characters and a lone surrogate: the program still writes a valid line under 4 KB.
- [ ] 1.3 Verify on the VM, as `Kid`, against the SYSTEM test program: "End task" in Task Manager, `taskkill /pid <pid> /f` and `Stop-Process -Id <pid>` each fail with "access denied"; `Kid` cannot suspend it (`NtSuspendProcess` through PowerShell gives access denied); with `DOTNET_STARTUP_HOOKS` set in `HKCU\Environment` to a test DLL of `Kid`, a new start of the test program does not load that DLL (no log line of the DLL).
- [ ] 1.4 Verify on the VM: `Kid` signs out while the SYSTEM test program runs and the service ends it at `WTS_SESSION_LOGOFF`; the sign-out completes in normal time and `query session` shows no session of `Kid` after it. Record whether `AssignProcessToJobObject` accepts the SYSTEM test program in the session of `Kid` for a job of the service in session 0. Then end the test service with `taskkill /f` as an administrator: the SYSTEM test program ends within 5 s (broken pipe), with or without the job.
