# Tasks

All VM checks run on test VM 102 as `Kid` in the Proxmox console (noVNC or SPICE), not over RDP. Before you install the service, check that the snapshot `test-base` exists (`docs/vm.md`). Use a test exe in Games with a Games limit of 2 minutes, as in `add-app-categories` task 6.2. Record each VM result with date and times in this file and in the PR.

## 1. Prerequisite and VM spike: Windows behaviour that the design assumes

Do this group before group 3. If a check fails, stop and run `/opsx:update` with the fallback that design.md names. Tasks 1.2 and 1.5 are gates for false counts and false locks: a fail-closed rule that charges or locks a normal session in a common case is a failed check too. The spike programs go in `scripts/vm/spike/` (outside the product). Build them on the Mac and publish them self-contained for `win-x64`. Record each measured value (times, counts, error codes) in this file.
